# 弦音全站 QA 与性能优化报告 · 2026-09-08

测试对象：[正式网站](https://rexrockya.github.io/tuner/)。基线为 `7aeabe3`，发布目标为 GitHub Pages 的 `main:/docs`。本轮先记录基线、复现缺陷，再修复、回归，并补做真实浏览器操作与性能观察。

## 验收结果

- 原有 `npm test` 回归通过；新增 **45 个功能场景全部通过**。另有音频加载、停止尾音、钢琴加载竞争等独立回归，均加入 `npm test`。
- 2,525 条乐句、615 种实际和声进行均验证；原创生成补测 12,000 组调性、和弦及随机种子组合。
- 全部 13 份乐谱、25 种移调共 **19,100 次钢琴采样映射比较通过**，确认没有因减载更换音区映射或丢失力度层。
- 真实 Chromium 浏览器完成桌面、375 px 手机竖屏、844 px 横屏操作检查，补正两处手机布局问题。浏览器控制最初超时，后续通过 DOM 通道恢复；不能把前半程的模拟结果当成真实浏览器结果。
- 声学测量、实体 iPhone/Safari、跨设备同步房间和真实账号写入没有完成，详见验证边界。

## 发现并修复的问题

| 问题 | 修复及复测 |
| --- | --- |
| 麦克风等待授权时离页仍启动；连点产生多条流；创建音频上下文失败泄漏流 | 在等待前建立取消句柄和请求代次；所有退出路径释放资源。三个场景均通过 |
| `#metro` 未处理、非法转义的乐谱 URL 抛异常、离开乐句后残留旧 hash | 统一栏目路由和 hashchange；解码异常回到曲库。直接访问与切页通过 |
| Jam 等待音色时松键，随后产生长音；等待播放/录制时关页仍启动 | 在 await 前记录可取消的按键/请求；关闭、切页和失焦释放。播放与录制竞争均通过 |
| 错误结构的 Jam 存储中断整站导航；无法写入时中断编辑；无效乐句索引导致启动崩溃 | 验证存储结构/索引；Jam 写入失败保留本次编辑。受控异常通过 |
| 播放位置每 25 ms 覆盖正在输入的 BPM | 仅同步变化值，编辑时保留输入，离焦显示合法范围。真实输入 120 保留 |
| `CmMaj7` 无法读取，但程序会输出此名称 | 统一小大七名称解析；原名及别名回归通过 |
| 原乐句伴奏关闭后低速下仍留音约 2.195 秒 | 跟踪声部、取消包络、淡出并停止。模拟停止上界 30 ms |
| 调音算法低音漏检、高音偏差大、白噪声误报 | 改为可复用缓冲的 YIN、完整首个阈值谷与插值；降低至约 20 次/秒分析 |
| 手机律动选择框被挤成截断文字，顶部出现多余横向滚动条 | 保证律动框 118 px、调整导航间距；375 px 下五栏完整可见，无页面横溢 |

## 性能变化

同口径前后数据保存在 [qa-performance-data](qa-performance-data/)。下表区分资源预算、计算基准和音频调度；它们不能互相替代。

| 指标 | 优化前 | 优化后 | 测量含义 |
| --- | ---: | ---: | --- |
| 默认调音页已知资源，等参 gzip 估算 | 691,080 B | 约 105 KB | 约减少 85%；静态资源集合估算，非真实加载秒数 |
| 首屏执行 JS 源码 | 1,953,469 B | 约 263 KB | 约减少 86.5%；三个大型库改为按需加载 |
| Blues 12 个音源 | 3,070,296 B WAV | 1,031,145 B FLAC | 减少 66.42%；12 份解码 PCM 校验一致，保留 WAV 回退 |
| Für Elise 钢琴采样，OGG | 226 个 / 19.89 MB | 61 个 / 3.98 MB | 减少 80%；含全部 ±12 移调 |
| Rondo Alla Turca 钢琴，OGG | 19.89 MB | 4.95 MB | 减少 75.1% |
| Original Rags 钢琴，OGG | 19.89 MB | 13.72 MB | 减少 31%；该谱确实需要较宽音域和多个力度层 |
| 16 节/90 音符，无变化的位置刷新中位 | 0.4971 ms | 0.0026 ms | Node/jsdom 同机 1,000 次；DOM mutation 从每次 7 个变成 0 |
| 教学↔节拍导航中位 / P95 | 1.96 / 2.56 ms | 0.79 / 1.13 ms | jsdom 业务/DOM 处理；去掉非 Jam 页面上的整套 Jam 重绘 |
| 16 小节生成与 TAB 渲染中位 | 8.635 ms | 7.001 ms | jsdom；保留立即响应，不增加人为 debounce |
| 调音单次计算中位范围 | 7.49–8.19 ms | 0.026–0.494 ms | 44.1/48 kHz，4096 输入帧；新耗时随音高变化 |
| 热伴奏播放的调度提前量 | 40 ms | 25 ms | 模拟 AudioContext 中的计划时间；不是扬声器首音 |

首屏新增了缓存友好的 `app.js`，全部普通脚本按 `defer` 顺序执行。**defer 仍然下载、解析和执行脚本**；真正省下首屏资源的是把 Tone、OSMD、fflate、完整乐句目录及隐藏媒体移到需要时加载。三库改为同站托管，附原许可证及来源校验。背景预热不调用 resume、不发声，并尊重节省流量设置。风琴波形和成功解码的采样复用，失败可重试。

### 真实浏览器观察

桌面 Chromium 的本地同源诊断框架：DOMContentLoaded 76.5 ms、load 83.3 ms、FCP/观察到的 LCP 76 ms；这是本地未压缩 HTTP 服务，**不是正式站广域网性能**。

该会话操作教学、和声输入、创作、重新生成和播放：Event Timing 观察到的最大交互时长 72 ms，点击/输入捕获至下一次 rAF 为 12.5–36.6 ms，未观察到 ≥50 ms 长任务。rAF 终点在绘制前，不能称为完整呈现时间；少量会话的最大值也不等于真实用户 INP。原始摘要：[browser-local.json](qa-performance-data/browser-local.json)。

正式站 HTTP 基线为 35 个资源 × 3 次请求。105 次中有 6 次失败或未完成下载，其中 4 次虽返回 HTTP 200 但下载超时，已单列，不当作成功。三次首页完整请求分别约 6,698 / 431 / 1,000 ms，说明网络波动很大，不能用单次快慢声称优化收益。可复用的被动诊断页只采集性能条目、元素 tag/id，不采输入值，不自动点击，不上传数据。

## 验证边界与剩余限制

- 未测实体麦克风输入至扬声器输出的声学延迟，未对 Blues 味道作真人听感验收。真实浏览器验证的是采样加载、播放状态推进、交互和错误日志。
- 未在 Safari/iOS、Android WebView/APK 与蓝牙音箱逐一实测；FLAC 不支持时的 WAV 回退已通过模拟故障验证。
- 账号、Flat 和房间协议已完整模拟测试，真实操作限于只读/界面检查；没有为 QA 写入真实公共房间、创建真实账号或修改用户云数据。
- 完全禁止 localStorage 读取的特殊浏览器策略仍可能影响旧模块启动；本轮验证了损坏数据恢复与 Jam 写入失败降级。普通浏览器模式、无缓存/首次使用和坏 JSON 不属于这一限制。
- 只有极弱基音、单独很强二/三次谐波的合成信号仍可能识别为泛音；含噪信号会降低精度。标准 28 组测试最大误差 1.765 cents，压力测试的 25% 白噪声混合最高约 8.77 cents。
- 公版在线谱、原乐句 PNG/MP3 和部分旧音色仍有外部依赖；大型宽音域钢琴谱首播仍需下载，不承诺瞬间加载。
