# 弦音全站 QA 与性能优化报告 · 2026-09-08

测试对象：[正式网站](https://rexrockya.github.io/tuner/)。基线为 `7aeabe3`，发布目标为 GitHub Pages 的 `main:/docs`。本轮先记录基线、复现缺陷，再修复、回归，并补做真实浏览器操作与性能观察。

## 验收结果

- 原有 `npm test` 回归通过；首轮 45 个功能场景、本次复核追加 10 个存储场景，共 **55 个功能场景全部通过**。另有音频加载、停止尾音、钢琴加载竞争及首屏资源预算等独立回归，均加入 `npm test`。
- 2,525 条乐句、615 种实际和声进行均验证；原创生成补测 12,000 组调性、和弦及随机种子组合。
- 全部 13 份乐谱、25 种移调共 **19,100 次钢琴采样映射比较通过**，确认没有因减载更换音区映射或丢失力度层。
- 真实 Chromium 浏览器完成桌面、375 px 手机竖屏、844 px 横屏操作检查，补正两处手机布局问题。浏览器控制最初超时，后续通过 DOM 通道恢复；不能把前半程的模拟结果当成真实浏览器结果。
- 声学测量、实体 iPhone/Safari、跨设备同步房间和真实账号写入没有完成，详见验证边界。

### 真实浏览器观察

桌面 Chromium 的本地同源诊断框架：DOMContentLoaded 76.5 ms、load 83.3 ms、FCP/观察到的 LCP 76 ms；这是本地未压缩 HTTP 服务，**不是正式站广域网性能**。

该会话操作教学、和声输入、创作、重新生成和播放：Event Timing 观察到的最大交互时长 72 ms，点击/输入捕获至下一次 rAF 为 12.5–36.6 ms，未观察到 ≥50 ms 长任务。rAF 终点在绘制前，不能称为完整呈现时间；少量会话的最大值也不等于真实用户 INP。原始摘要：[browser-local.json](qa-performance-data/browser-local.json)。

正式站发布后同源 Chromium 诊断框架，首次这次导航的 TTFB 376.2 ms、DOMContentLoaded 1,107.9 ms、load 1,109.2 ms、FCP/观察到的 LCP 964 ms。15 个同源初始资源传输 89,298 B，加文档 20,716 B，合计约 110 KB（含响应头）；未加载三大库或乐句媒体。教学/筛选/创作/播放会话中，最大观察交互时长 64 ms、capture→rAF 最大 30.8 ms，无 ≥50 ms 长任务。12 个 FLAC 全部成功，单资源观测下载时长约 0.73–2.64 秒；预热可在编辑和声期间完成，首次网络下载仍存在。浏览器缓存没有强制清除，不能称为严格冷缓存；以上是当前网络的一次真实观察，不能直接和本地计时比较。

缓存后再次导航：DOMContentLoaded 24.9 ms、load 29.9 ms、观察 LCP 76 ms。同一音频上下文再次播放时，点击至按钮 `aria-label` 切换为暂停为 **2.4 ms**；该次页面重载后预热播放为 39.7 ms。此项仅表示播放器 DOM 状态已就绪，不代表完成绘制，后面仍有 25 ms 调度提前量和设备输出延迟。修正诊断页的祖先选择器后复测通过，完整摘要：[browser-production.json](qa-performance-data/browser-production.json)。

正式站 HTTP 基线为 35 个资源 × 3 次请求。105 次中有 6 次失败或未完成下载，其中 4 次虽返回 HTTP 200 但下载超时，已单列，不当作成功。三次首页完整请求分别约 6,698 / 431 / 1,000 ms，说明网络波动很大，不能用单次快慢声称优化收益。可复用的被动诊断页只采集性能条目、元素 tag/id，不采输入值，不自动点击，不上传数据。

## 验证边界与剩余限制

- 未测实体麦克风输入至扬声器输出的声学延迟，未对 Blues 味道作真人听感验收。真实浏览器验证的是采样加载、播放状态推进、交互和错误日志。
- 未在 Safari/iOS、Android WebView/APK 与蓝牙音箱逐一实测；FLAC 不支持时的 WAV 回退已通过模拟故障验证。
- 账号、Flat 和房间协议已完整模拟测试，真实操作限于只读/界面检查；没有为 QA 写入真实公共房间、创建真实账号或修改用户云数据。
- 存储拒绝/写满时的启动与编辑中断已在复核迭代修复；故障期间暂存只在当前页面有效，刷新可能丢失。无法持久删除 Flat 令牌时会保留说明，当前页屏蔽旧值，但刷新后仍须由浏览器清除网站数据，不能把内存删除标成永久删除。
- 只有极弱基音、单独很强二/三次谐波的合成信号仍可能识别为泛音；含噪信号会降低精度。标准 28 组测试最大误差 1.765 cents，压力测试的 25% 白噪声混合最高约 8.77 cents。
- 公版在线谱、原乐句 PNG/MP3 和部分旧音色仍有外部依赖；大型宽音域钢琴谱首播仍需下载，不承诺瞬间加载。

## 报告复核 → 补充迭代 → 发布判断

按用户追加的发布流程，先审阅报告、独立复核音频与页面风险，再决定是否继续迭代。复核开始时 `0fca5b2` 已在正式站 built；没有把此前已发布误写成仍未上线。本次先完成以下修正和文档，再发布下一版本。

**第一次判断：需要补充修复。** 报告原列的存储限制是可复现的启动缺陷：localStorage 属性/读取拒绝导致 lessons、metronome、scores 初始化失败；初始写满也会在默认音量/速度保存时抛错，主页面随后因节拍器 API 缺失而中断。只运行 app.js 且保留播放器占位对象的测试掩盖了依赖模块问题。因此新增测试移除占位，按 index 的真实顺序加载全部模块。

修复覆盖：正常保存、属性访问拒绝、getItem 拒绝、初始写满、运行中写满、权限恢复、失败删除的旧值屏蔽、Flat 删除/临时连接提示可见性、首次节拍主持房间在写满时进入。五栏切换、速度和双音量、教学收藏、原创保存、Jam 认领/示范均在故障条件下操作。收藏失败不声称永久保存；不更改浏览器原生 localStorage，不上传临时内容。

**第二次判断：满足发布条件。** 全量 `npm test` 通过，后补的房间场景和资源预算检查分别复测通过，合计 55 个补充功能场景。实际 OSMD 使用仓库自带渲染器，35 小节整页与 375/844 px 回归通过；缺失文件改为明确失败，消除原本依赖本机缓存/可能跳过的验证缺口。可选 Worker 本次未更改，沿用此前 lint/测试通过结果。

本次真实 Chromium 在本地重新操作和声输入 → 创作 → 收藏 → 播放/暂停 → 刷新 → 找回收藏，全部通过；正常存储下异常提示隐藏，1265 px 窗口页面无横向溢出。存储拒绝/写满通过受控 API 注入验证，并未宣称改变实体浏览器隐私策略。此前正式站的音频/性能数据仍是原测量会话，未把它们冒充本次重新计时。

加入存储适配器后，默认页面 17 个资源，按提交的 LF 文本与逐文件 gzip 6 口径共 **105,565 B**，通过 **120,000 B** 预算；未重新引入首屏大型库，采样、钢琴映射和调度路径无新增改动。[当前资源明细](qa-performance-data/release-resource-budget.json)。

[PRD](../PRD.md) 已补齐教学验收、界面原则、性能口径和发布门槛；[HANDOFF](../HANDOFF.md) 已更新存储策略、延迟含义、FLAC/WAV、代码入口、复现/部署/回退步骤及真实浏览器结论。设备声学延迟、实体 Safari 与真人 Blues 听感保留为明确的后续验证项，没有以模拟通过来代替。

发布前结论：已知可复现阻断项清零，本轮停止继续扩展范围，进入推送和正式站文件验证；实际发布结果在下节核验后追加。
